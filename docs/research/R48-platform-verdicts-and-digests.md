### 陷阱
1) **ArkTS linter 禁内联对象字面量类型**：`Object literal must correspond to some explicitly declared class or interface (arkts-no-untyped-obj-literals)`（docs/ARKVM-RESEARCH.md:643 实测报错原文）——TimePicker 的 create 选项与 dateTimeOptions 字面量合法是因为对应**已声明** TimePickerOptions/DateTimeOptions；若在页面里给回调结果做临时结构（如 `let t: {h:number}={h:1}`）直接编不过。同表：eval/Symbol/生成器/#private 也禁（同文件 :635-642）。fixtures/*.ts 是 ets-loader 产物**不经检查器**，不要把产物能出现的构造误读成页面能写（:651-653）。
2) **枚举声明顺序 vs 数值**：TimePickerFormat 在 .d.ts 无显式赋值（time_picker.d.ts:79-100），数值**全靠声明顺序**——HOUR_MINUTE=0、HOUR_MINUTE_SECOND=1（native 生成枚举双证 arkoala_api_generated.h:7826-7829；C++ constants.h:464 同序）。dataset 必须记数值而非名字（scroll.js:36/image.js:20 惯例），且**任何“重排枚举/合并枚举”的再生成都会静默换值**。对照 CrownSensitivity 是**显式** 0/1/2（enums.d.ts:5144+）——两种形态混在同组件 surface 里，写映射表时别按同一假设。内部 ZeroPrefixType AUTO=0/HIDE=1/SHOW=2/OFF=3（time_format.h:34-39）另成一套，且 dateTimeOptions 走**字符串** "2-digit"/"numeric"（桥接 arkts_native_timepicker_bridge.cpp:404-420）——dataset 记录时要把字符串映到数值再存。
3) **ets-loader 属性表过期**：timePicker.json/generated-components.js:3062-3078 只登记 9 个 attrs，缺 format/start/end/onEnterSelectedArea/digitalCrownSensitivity——若不写 TIMEPICKER_ATTRS 拦截，`onEnterSelectedArea(fn)` 会落进 area.js:337 通用规则变成 addEventListener('enterselectedarea') **永不触发**（area.js:313-317 注释点名的静默失效族，坑 86）；create 的 {selected,format,start,end} 会被 applyCreateArgs/applyNativeArgs（main.js:495-535）**无声丢弃**（无 Date 分支）——必须工厂自读（image.js:75 先例）。
4) **headless 虚拟时间：rAF/scroll 事件不可靠**：坑⑧——rAF 在 headless 节流不确定（DEVELOPING.md:452）→ 吸取 animator.js 教训**绝不用 rAF** 驱动档位动画/吸附，用 setTimeout；scroll.js 先例是“程序化改 scrollTop 后同步派发 'scroll'”（scroll.js:114-115）+ 80ms settle 收口（:107-112）——本组件 onChange 模拟“动画完成”用同款定时器，断言走**轮询**而非固定 tick（README:929/DEVELOPING.md:452）。坑 89：轮询上限必须 < 虚拟时间预算(8000ms)−前置耗时（DEVELOPING.md:445/:450 区域，run_one 用 --virtual-time-budget=8000）——tp1+tp2+tp3 三个选择器若都轮询，预算会被吃光、破坏态 0 红假死（run.sh:24-36 依赖 emit 出的 PASS 行计数）。坑 87：@State 写入→重渲染有批量调度延迟，log 断言前必须 await tick（DEVELOPING.md:437）。
5) **重渲染重复应用（坑 88 族）**：@State 变化会把 `.onChange(cb)`/`useMilitaryTime(...)` 再跑一遍——回调必须**覆盖**注册（__tpCbs 覆盖，scroll.js:52-66/animator.js:43-47），selected/format 重复应用要同值守卫（animator.js:21-23 framesKey 先例），否则监听翻倍、档位被重置回 selected。真机侧对应物：isFiredTimeChange_ 回声抑制（row:563-569）——onModifyDone 防两向绑定回声，DOM 版需等价守卫。
6) **默认值依赖“系统”而非常量**：useMilitaryTime 未设置时真机取 `SystemProperties::Is24HourClock()`（row.h:818/h:277-281），浏览器/Electron **没有**系统 12/24 时钟偏好——必须显式定一个文档化缺省（建议 true，同时 data-use-military-time 未设时不写键以示“系统缺省”）；注意 create JSDoc 写 “uses the 24-hour time format by default”（d.ts:208）而属性 JSDoc 写 “system time format is used by default”（d.ts:254-255），两句并存，实现取舍要留注释。selected 缺省=当前系统时间（PickerTime::Current, picker_data.cpp:254-267）→ **fixture 必须显式传 selected**，否则断言非确定。
7) **onChange/onEnterSelectedArea 时序与文档张力**：d.ts:451 说 onChange “only after the scroll animation completes”，而引擎代码里 onChange 由 InnerHandleScroll 在**index 实际跳档时**发（picker_column_pattern.cpp:440-441；拖拽整档 :479-481、拖尾半档 :569-572、toss 帧内 :450-501），300ms 吸附动画（:30/:573）在跳档**之后**跑；onEnterSelectedArea 半档先发（timepicker_column_pattern.cpp:307,326-330）。DOM 版用 settle 定时器对齐文档语义时，要在注释里记下这处“文档 vs 代码”差异，fixture D 组断言的是 settle 后的最终顺序 E→C，不依赖帧内中间态。
8) **无 DOM 对应的硬件语义**：enableHapticFeedback（需 ohos.permission.VIBRATE，d.ts:509-510）、digitalCrownSensitivity、toss 惯性曲线、系统主题 vp 数值（picker_select_divider_spacing/gradient_height 在设备主题里，仓库 not-found，picker_theme.cpp:82/84 缺省 0.0_vp 不可用）→ 全部 data-*+layoutWarnings，不模拟（scroll.js:67-70 fling 先例）；横屏 3 行（sys.float 资源）DOM 固定 5 行需注明分歧。9) **run.sh 断言计数守门**：提交说明里手写的“（N 条断言）”必须与运行期 PASS 行数一致（run.sh:24-36 注释：静态 grep check( 会把没跑到的算进去），新页别漏 assert-counts 闭环。
