### 逐条关键结论（一句话）

1. **R5a**：`ets-loader` 与 `components/*.json` **未声明任何 OSS 许可**（`license` 字段缺失、无 LICENSE 文件），
   而 `ets/component/*.d.ts` 121/121 声明 Apache-2.0 → 派生物不得标 Apache-2.0；纯本地开发不受影响。
2. **R9/R10**：ArkUI 的轨道尺寸里**裸数字是 vp**，直传 CSS 会让整条声明作废且不报错；`Tabs.onChange`
   落到通用事件分支会变成**永不触发的监听器**。
3. **文档守卫**：`ARCHITECTURE.md` §6 整块实测数字以前靠人肉同步，R5a 提交就漏了一行 →
   现在 `npm run check` 第 3 步逐行比对。
4. **R11**：本 SDK 的 `SwiperInterface` **只有** `(controller?: SwiperController)` 一个重载 ——
   create 的参数就是**控制器实例**，不是 options 对象（与 `Tabs` 不同）。
5. **R12**：`Navigation` 的 builder **由运行时调用**（不在 `initialRender` 里）→ 建树要走
   "预压容器 → 调 builder → 还原栈 → **校验产出** → 失败回滚"；漏了校验会留下"路径项存在但节点不存在"的幽灵。
6. **R14**：`.d.ts` 的 JSDoc 纠正了三处 —— `bias` **默认 0.5**（不写=居中，不是"不生效"）、
   `GuideLinePosition` 只有 `start`/`end`（没有 `percent`）、`Axis.Vertical` 是**竖线**（锚水平位置）。
7. **R13**：`Gauge` 的 `endAngle` **默认 360**，而一条 SVG arc 起终点重合时**渲染成空** → 必须拆两段；
   断言不该钉半径（那是实现选择）。
8. **R15**：`measureText` 的 JSDoc 明确"**总是量单行**，布局约束不影响结果"；实现取向是
   **让浏览器自己排版**（离屏元素 + `Range.getClientRects()`），宽高与真实 `Text` DOM 逐像素一致。
9. **R16**：虚拟列表偏移改成"逐项 advance 的前缀和"+ 渲染后实测回填 + **滚动锚定**；
   修掉 4 个真 bug（flex gap 多算 spacer / 渲染空间与数据空间下标混用 / 锚定 delta 算太早 / 窗口没变不重设 spacer）。
10. **R17**：`onMeasureSize` **不是**尺寸回调而是**自定义布局协议**；`@Entry` 的 build 只能有一个容器根节点；
    带链式属性的自定义组件会被包一层编译器合成的 `__Common__`。
11. **R18**：`mimeType` 的权威语义是 **"Actual image format"**（解码后的真实格式）→ 要嗅探字节魔数，
    不能用响应头；`@ohos:media` 实为 `@ohos.multimedia.image`。

## 4. 方法论沉淀（本会话最有价值的部分）

### 4.1 "断言无效"的 5 种形态 ⚠️ 本会话反复出现

破坏验证（把实现改坏、看断言是否真的红）是这里最有效的质量手段，但它抓出过**五次**
"断言其实没测到东西"：

| # | 形态 | 实例 | 修法 |
|---|---|---|---|
| 1 | **断言与实现恰好同值** | 错轴返回 0 vs 横线自身 `x=0` | 换**区分度更高**的输入（改用 `Center` → 0 vs 150） |
| 2 | **中间量在最终结果里被约掉** | `height = 行数 × 单行高`，从高度反推行数永远对 | **把被约掉的中间量单独暴露**再断言（`__arkui_dom_countLines`） |
| 3 | **用错坐标空间/量纲** | `getBoundingClientRect` 含 `translate(-100%,-100%)`，`offsetLeft` 不含 | 先问"**这个量在哪个坐标系/单位下**" |
| 4 | **没问清尺寸是谁给的** | 以为"不设宽度就是单行"，实际受容器约束 | 用**元素自身实测值**自洽推算 |
| 5 | **错误的实现也可能碰巧得到正确值** | `mimeType` 写死 `image/png` 也通过 | **造一个能让错误实现暴露的输入**（真 JPEG + 伪装文件） |

**统一判据**：**"把实现改坏"必须真的红；改坏了还不红，就是断言没测到。**

### 4.2 破坏验证必须能"看到全部失败项"

一次断言抛异常会**吞掉后面所有断言**（测试体是一个大 `try`）→ 破坏验证会给出虚假结论。
现在所有新测试用 `group(name, fn)` **分组隔离**，抛错记为该组 FAIL、其余组照跑。
（`test/drawdemo.html` 是模板。）

### 4.3 待办清单记录"意图"，`.d.ts` 才是"接口形状"的权威

本会话**两次**发现 ROADMAP 的前提不准：R17 的 `onMeasureSize`（其实是自定义布局协议）、
R18 的 `@ohos:media`（其实是 `@ohos.multimedia.image`）。
→ 动手前一律回 `.d.ts` 核对；并且**字段名往往说不清语义，必须读 JSDoc**：
`bias` 的 `@default`、`measureText` 的 "always single-line"、`mimeType` 的 "Actual image format"。

### 4.4 需要"和真实渲染一致"的测量，就让引擎自己去做

文本换行用真实 DOM 排版、图像尺寸用真实解码器、变高列表用渲染后回填 ——
"自己按字符宽度累加/自己解析文件头"一定会在字距、字体回退、禁则处理、格式变体处分叉。

### 4.5 交付物里的数字必须可复核（仍有一处缺口）

- 已加守卫：`ARCHITECTURE.md` §6 的整块实测数字（`npm run check` 第 3 步）。
- ⚠️ **未加守卫**：README/ROADMAP 里**手写的"（N 条断言）"**。本次归档复核时发现
  **9 个数字里有 2 个是错的**（`swiper` 41→实际 38，`mimeType`/`measimage` 14→实际 13）——
  R11 后来把 2 条弱断言并成 1 条但没同步计数，R18 是数错了。**已修正**，但根源（无守卫）仍在，
  建议照 §6 的做法加第 6 步：从 `run.sh` 解析用例→页面映射，静态数出每个测试页的 `check(` 数量并与文档比对。
  （commit message 里的旧数字不改写历史，以本文件为准。）

## 7. 已知限制（汇总，权威以 `CAPABILITY.md` 为准）

- **手势**完全未实现（含 `Swiper` 的滑动翻页）；**动画/过渡**未实现
- `Navigation` 无标题栏/工具栏/返回按钮，只有 Stack 语义；`@Entry`/组件级 `onMeasureSize` 的
  生命周期全序**部分为推断**（未在真机核对）
- `Grid` 无模板时的 `cellLength` 自适应未实现；`chainMode` 未实现；环状锚定只记警告
- `LazyForEach` 的实测高度**按索引**存（数据源增删/重排后整表失效）
- 图像模块只有 `createImageSource(uri)` + `getImageInfo*` + `release`；`stride`/`density`/`pixelFormat` 回常量 0
- 浏览器侧持久化是 `localStorage`（非真文件系统）；`@ohos:media`/`notification` 等未实现
- 未实现项一律**记 `layoutWarnings` 或响亮报错**，不静默
